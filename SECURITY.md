# Security Policy

## Project scope

This repository is a research and portfolio project. It is not intended for production deployment or connection to safety-critical, industrial, railway, or other operational systems.

Security reports are welcome for vulnerabilities in the repository's code, build configuration, dependency configuration, and GitHub Actions workflows. Reports about hypothetical weaknesses in external systems or unsupported deployment environments are outside the project's scope.

## Supported versions

Security fixes are considered for the latest state of the default branch. No release line or service-level response commitment is currently offered.

## Reporting a vulnerability

Please do not disclose suspected vulnerabilities in public issues, pull requests, discussions, or social media.

If GitHub's private vulnerability reporting is enabled for this repository, use the **Report a vulnerability** option in the repository's Security tab.

If that option is unavailable, contact the repository maintainer privately through the contact options on the maintainer's GitHub profile:
https://github.com/silvatechf

Include, where possible:

- A concise description and potential impact.
- The affected file, component, commit, or version.
- Reproduction steps or a minimal proof of concept.
- Any relevant logs, without secrets, personal data, or third-party confidential information.

The maintainer will review reports in good faith and may request additional details. There is currently no guaranteed response or remediation timeline. Please allow reasonable time for investigation and coordinated remediation before any public disclosure.

## Safe-harbor expectations

Do not access, modify, disrupt, or exfiltrate data from systems that you do not own or have explicit permission to test. Do not perform denial-of-service testing, social engineering, or testing against live safety-critical or operational infrastructure.
